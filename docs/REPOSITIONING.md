New work for the software/protocol reframing lives here.

## Claim shift

| LSSP (rejected) | This path |
|-----------------|-----------|
| “Novel Monte Carlo comparison of preprocessors” | “Open, matched nested-CV **benchmarking toolkit** for local-regression feature maps” |
| Regimes prove when each map wins | Regimes are **acceptance tests / validation suite** for the protocol |
| Findings that maps win when designed to win | Expected regime outcomes are a **feature** (positive controls), not the scientific punchline |
| Apps as brief illustrations | Apps as **worked examples** of the software workflow |

**Primary deliverable:** installable/reproducible Python package + short scholarly article describing design, API, validation suite, and usage.

**Secondary:** frozen Monte Carlo tables remain as regression tests / numerical evidence that the protocol behaves as documented.

## Why LSSP failed (use this in cover letters)

Editors read the paper as assembling standard nested CV + known maps, with simulations engineered so winners are foreseeable. For a **methods** journal that critique is fair. For a **software/protocol** venue, the response is: the contribution is the reusable matched protocol, diagnostic, and reproducible suite—not a new estimator.

## Do not claim

- A new local-regression theory result
- Universal superiority of any map
- That “designed regimes” alone establish methodological novelty
